Uma experiência, três destinos

Selecionar trabalho → revisar contexto e código → escolher destino

↳ Outro agente · iniciar com contexto
↳ Outro desenvolvedor · enviar pacote portátil
↳ Outra conta · abrir nova sessão isolada

A primeira entrega prova a passagem entre pessoas. A dashboard reutiliza esse núcleo; não exige criar uma IDE ou um servidor.

Invariantes desde o primeiro dia

Exportação básica sem chamadas a modelos. Destinatário consegue ler o pacote sem instalar a ferramenta. Omissões explícitas. Credenciais nunca acompanham contexto. Exportar não faz commit ou push no projeto do usuário. Uma sessão nova não renova a cota do provedor.

Um histórico que explica as decisões

Planejar → implementar em branch → revisar o diff → validar o resultado → integrar.

  • Branches curtas codex/<assunto>; PR e squash quando houver remoto.
  • Critérios de aceite por entrega, testes observáveis e fixtures sintéticas.
  • Autorrevisão identificada; revisão independente apenas quando realmente realizada.
  • Decisões duradouras em ADRs; nada de inventar CI, aprovações ou métricas.
  • Autonomia para todo o ciclo acordado, sem descartar trabalho de terceiros.

Referências e limites do escopo

Orca: referência pesquisada para captura de contexto e leitores de sessão. ai-memory: referência pesquisada para memória contínua e handoffs. Pesquisa de código e documentação; não houve validação em execução desses projetos.

Não entram no MVP: IDE própria, servidor compartilhado obrigatório, memória organizacional completa, sincronização entre máquinas, seleção automática de contas ou troca silenciosa de credenciais. A compatibilidade universal é direção de produto; suporte efetivo será publicado por agente e versão.

Documento de planejamento · Nada nesta página consulta contas, executa agentes ou transmite conversas. Preferências dos filtros não são persistidas. Sem dependências externas.
